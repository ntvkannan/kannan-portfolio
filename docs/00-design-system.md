# 01. DESIGN SYSTEM PURPOSE

This design system defines the visual and interaction foundation for Kannan Thangavel's personal website.

The website must communicate three things clearly:

1. Senior UX/UI expertise
2. Strong frontend development capability
3. Ability to provide design services for freelance/client work

The website itself should also become the first practical demonstration of:

UX Strategy → UI Design → Design System → Frontend Development

The design system must therefore be professional enough for recruiters and flexible enough for freelance/client audiences.

# 04. DESIGN PRINCIPLES

## 04.1 Clarity First

Every section must have a clear purpose.

Avoid visual decoration that does not improve communication.

---

## 04.2 Portfolio First

The actual work should be the primary visual evidence.

Do not use decorative graphics to compensate for weak content.

---

## 04.3 Typography Creates Hierarchy

Use typography, spacing and layout to establish importance.

Avoid excessive cards and borders.

---

## 04.4 Design-Led, Not Developer-Led

The website should demonstrate UX/UI capability.

Avoid:

- Code-editor backgrounds
- Terminal graphics
- Excessive technology logos
- Matrix-style effects
- Generic developer animations

Technology should support the story, not become the visual identity.

---

## 04.5 Progressive Disclosure

Do not show everything immediately.

Homepage:

Short introduction → selected work → capabilities → services → CTA

Detailed information belongs on individual pages.

---

## 04.6 Authenticity

Only show real projects, real experience and real capabilities.

Never invent:

- Client testimonials
- Project metrics
- Awards
- Users
- Results
- Client logos
- Development contributions

---

## 04.7 Scalable Portfolio

The system must support future projects without redesign.

Current:

Professional UX/UI
Client & Brand Work
Development / Building

Future:

Professional UX/UI
Client & Brand Work
Product Design & Development

The website must follow accessible design principles.

Required:

- Semantic HTML
- Proper heading hierarchy
- Keyboard navigation
- Visible focus states
- Accessible contrast
- Descriptive alt text
- Form labels
- Accessible buttons
- Accessible navigation
- Reduced-motion support

# 52. FOCUS STATES

All interactive elements must have a visible focus state.

Do not remove browser focus indicators without replacement.

---

# 53. MOTION

Motion should be subtle.

Use animation for:

- Page entrance
- Section reveal
- Hover
- Navigation
- Image interaction

Avoid:

- Excessive parallax
- Long animations
- Constant movement
- Distracting effects

Respect:

prefers-reduced-motion

# 54. ANIMATION TIMING

250–350ms

400–500ms
